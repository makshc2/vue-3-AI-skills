# Improvement roadmap — frontend-agent-skills

> Результат багатоагентного аудиту (2026-10-01): 9 незалежних аналітиків, по дві незалежні перевірки на кожну партію пропозицій, синтез і критик. Мета аудиту: **якість** використання скілів, **обов'язковість** (скіл підхоплюється, коли потрібен) і **економія токенів/грошей**.
>
> Це аналітичний документ, не специфікація: жодних змін у `skills/`, `bin/` чи тестах він не вносить. Кожен пункт слід оформлювати окремою OpenSpec-зміною (`/opsx:propose`), бо в репозиторії дозволена одна активна зміна.

## Як читати цифри (важливо)

- Усі виміри зробили агенти під час аудиту, вони не перезапускалися окремо. Ключові числа варто перевірити перед рішенням.
- Токени скрізь оцінені як bytes/4. Реальні виміри критика (Claude Code 2.1.286, Haiku 4.5) на 6–33% вищі: наприклад `vue-core` ≈1 970 токенів проти 1 676 за bytes/4. Відсоткові співвідношення зберігаються, абсолютні числа — мінімум.
- Економії з різних пунктів **не складаються**: частина рахує те саме двічі (наприклад `vueuse` у пунктах 1 і 9; `vue-axios` у 6, 7 і 11).
- У каталозі `skills/` **33** файли `SKILL.md` (не 41), ще 9 — dev-скіли в `.agents/skills/`.
- Твердження про Cursor та Amp не підтверджені (їхні офіційні доки були недоступні агентам) і позначені `unverified`.
- Агент-перевіряльник здійсненності для партії ACT (описи) повернув порожній результат: ті пропозиції пройшли лише перевірку фактів. Їх перекриває пункт 6.
- Майже кожну пропозицію перевіряльники повернули як `revise`, тобто з поправками; поправки вже враховано нижче. Одну пропозицію (DUP-5) відхилено.

## Підсумок

The biggest wins are not new features but concrete defects (CI red on Node 20, 268 dead vueuse links, skills installed where Claude Code never looks, contradictory rules inside the default 9, and no trigger measurement at all) plus bodies that cost about 29x a description on every load. Fix defects and install targeting first, add one contract/budget test layer and one eval harness, and only then use that evidence to rewrite descriptions, trim the default-install hot path (about -2.3k tokens per Vue task) and decide whether router/hook enforcement is worth its tokens.

### 5. One trigger-eval harness (60 prompts, expect/forbid, loaded-tokens per prompt) preceded by a $0.05 overhead probe

- **Зусилля:** M  
- **Цілі:** mandatory-use, quality, token-savings  
- **Залежить від:** rank 1  
- **Злиті пропозиції:** ACT-5, MEAS-2, MEAS-3, ENF-5

**What.** Mandatory use is currently a hope: no fixtures, no measured recall, no measured false-activation, and every description change so far was made by feel. This is the gate for ranks 6, 7, 10 and 14 and replaces four overlapping measurement proposals with one tool.

**How.** Phase 0 (S): scripts/probe-overhead.mjs installs none / default 9 / --all into tmp dirs and runs `claude -p 'reply OK' --model claude-haiku-4-5 --output-format json` 3x each, reading usage; the deltas are the true per-session listing cost (expect about 612 and about 2,230 tok by bytes/4; a smaller --all delta would reveal budget truncation). Phase 1 (M): evals/triggers/cases.jsonl, about 60 cases {prompt, profile, expect, allow, forbid, tags}: 2 positives per skill for the default 9 and the confusable clusters (1 literal-keyword, 1 paraphrase), sibling negatives (UserCard.spec.ts expects vue-testing and forbids javascript-testing; '[Vue warn] hydration mismatch' expects vue-debug; 'fetch users with ofetch' forbids vue-axios; a figma.com link expects design-transfer + figma-intake and forbids design-from-screenshot; 'build a login form' forbids javascript-dom), about 15 non-frontend negatives, 30% held out. Runner: prefer `claude plugin eval` (case + tool_used: Skill grader, skills flattened into a temp plugin; confirm availability) else `claude -p --output-format stream-json --verbose --max-budget-usd N` counting Skill tool_use events, in an isolated config (--setting-sources project, no user skills, CLAUDE.md or MCP). Metrics: per-skill recall; false-activation on forbid/negatives; sum of body tokens of unexpected loads per prompt; for router/hook work LBE = a Skill load before the first Edit/Write on a routed path, counted from transcript order (typed /skill via UserPromptExpansion and Reads of SKILL.md count as loads). Configs: A today, A' one sentence in CLAUDE.md, B router, C hooks. Run manually or on release only, 3 runs, report ranges (differences under about 25 pp at n=30 are noise), calibrate cost on 5 runs first, add a Sonnet 5.5 spot check on about 30 cases. Phase 2 (optional, L, only if Phase 1 shows signal): 4-task A/B bench (Pinia store, typed props/emits, router param lifecycle, negative control) x A0/A1 (+A2 for debug) x n=3 with hidden vitest + vue-tsc + eslint, --allowedTools for the check commands, gate on aggregates only (cost <= baseline x 1.10, negative-control overhead <= +3%).

**Expected effect.** Turns 'skills reliably used' into numbers (target recall >= 0.90, false-activation <= 0.10, mean unexpected-load tokens per cluster prompt down >= 10%). Confirms or refutes the unmeasured co-loading hypothesis (testing triad 4,735 vs 1,342 tok) and whether a router beats one CLAUDE.md sentence. Harness cost is tens of dollars (estimate: $15-45 for about 108 router runs, about $1.5-4.5 per 150 Haiku cases); end-user cost 0 (not in package.json files).

**Caveat.** Claude Code only; a Haiku result may not transfer to the Sonnet/Opus models users run; LLM routing is nondeterministic and synthetic prompts bias toward the author's phrasing (seed 30% from real prompts). '--max-turns' is not listed in `claude --help` of the installed 2.1.286, use --max-budget-usd. Cursor and Amp routing is not measured. Dropped: BM25 offline tier, 150-case fixture set, router-based tests of disable-model-invocation (a free static assertion in rank 4), shipped telemetry.
